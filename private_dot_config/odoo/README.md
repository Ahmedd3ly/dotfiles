# Odoo client workspaces

```
~/Projects/odoo/
├── odools.toml                        GENERATED by `odoo-lsconf`: one odoo-ls profile per client
├── versions/<x.0>/{odoo,enterprise}   shared upstream code, never edited
└── clients/<client>/
    ├── .odoo-version                  e.g. 19.0 (the runner reads this)
    ├── odoo.conf                      from ~/.config/odoo/client.conf.template; addons_path lives here
    ├── .venv/                         Odoo requirements + client extras + pylint, pylint-odoo;
    │                                  site-packages/odoo-src.pth makes `import odoo` work (pylint)
    ├── .pylintrc                      -> ~/.config/odoo/client.pylintrc.template (only if src/ has none)
    └── src/                           client repo (stage branch)
```

`<client>` is used three times: as the folder name, in `odoo <client>`, and as the
database prefix (`<client>_dev`, `<client>_demo`). Keep it to lowercase letters, digits, `_` and `-`.

The commands live in `~/.config/zsh/conf.d/45-odoo.zsh` (tracked in the dotfiles repo).

## New client

```zsh
odoo-new <client> 19.0 stage git@github.com:<org>/<repo>.git
```

What it does, in order, stopping at the first failure:

1. creates `clients/<client>/src`, writes `.odoo-version`, clones the repo with submodules
2. `uv venv --python 3.12 .venv`, writes `odoo-src.pth` (so linters can `import odoo`), then installs
   Odoo's and the repo's `requirements.txt`
3. installs `pylint pylint-odoo` and links `.pylintrc` (skipped when `src/.pylintrc` exists)
4. writes `odoo.conf` from the template
5. runs `odoo-lsconf` (adds the client's odoo-ls profile) and `odoo <client> --version`

If it fails: fix the cause, `rm -rf ~/Projects/odoo/clients/<client>`, run it again.

- **Submodules** (OCA, third-party): add each submodule folder that holds modules to
  `addons_path` in `odoo.conf`, then run `odoo-lsconf`.
- **Python**: 3.12 works for 19.0 and 20.0. For older versions, check the version's
  source-install docs and run `ODOO_PY=3.10 odoo-new ...`.
- **Running two clients at once**: give one of them a different `http_port`.

## Daily use

```zsh
odoo <client>                          # serve on 127.0.0.1:8069
odoo <client> -d <client>_dev -u <module>
onv <client>                           # cd into the workspace + nvim
```

Database manager: <http://127.0.0.1:8069/web/database/manager>. Name every database
`<client>_...`, otherwise `dbfilter` hides it.

## Editor (Neovim)

- Open a client with `onv <client>`: the odoo-ls profile is picked from the folder
  Neovim starts in. Started anywhere else under `~/Projects/odoo`, odoo-ls stays idle.
- Under `~/Projects/odoo`, odoo-ls replaces pyright for Python; ruff, lemminx (XML) and
  pylint-odoo (on save, nearest `.pylintrc`) run alongside it.
- No format-on-save here (client repos): format on purpose with `<leader>cf`.
- After `git pull` or a branch switch: `:OdooLs restart` (file watching is off).
- Changed `addons_path` or added a client: `odoo-lsconf`, then `:OdooLs restart`.
- Health: `:checkhealth odoo_ls`. Server install and upgrades: RUNBOOK.md, "odoo-ls".

## Remove a client

```zsh
dropdb -U odoo <client>_dev            # repeat for each <client>_ database
rm -rf ~/.local/share/odoo/v<NN>/filestore/<client>_dev   # v19 for 19.0, v20 for 20.0
rm -rf ~/Projects/odoo/clients/<client>
odoo-lsconf                            # drop its odoo-ls profile
```
